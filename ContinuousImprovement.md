# Process Assurance vs Product Assurance

| Area                    | Process Assurance                                                | Product Assurance                                        |
| ----------------------- | ---------------------------------------------------------------- | -------------------------------------------------------- |
| Main focus              | How the work is performed                                        | Quality of the software product                          |
| Example in this project | Requirements review, coding standards, Git commits, test process | Validation logic, working booking feature, passing tests |
| Evidence                | Review checklist, commits, test plan, CI results                 | Test results, defect reports, working prototype          |
| Goal                    | Prevent quality problems                                         | Detect and confirm product                               |

Both assurance attribute are needed because they both contributes to creating a quality software implementation.
Process Assurance focuses on how the work is performed when creating the software, ensuring that the team is following coding standards
in order to minimize the software quality problems introduced during developement. 
Product Assurance ensures that the the product produced meets the standards and that all functionality have been tested in validation, wokring logic, 
and passing all test.
